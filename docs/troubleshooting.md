# Troubleshooting

[中文](troubleshooting.zh-CN.md) | **English**

## Start with diagnostics

```bash
ownpi doctor
ownpi info
```

- **Command not found:** add `~/.local/bin` to `PATH` as shown in [Getting Started](user/getting-started.md). To retain the change in new terminals, add the export to your shell's startup file.
- **Missing configuration or credentials:** run `ownpi setup`.
- **Model access fails:** verify the provider, Base URL, API key, and exact model name. The OpenAI-compatible setup option requires the Responses API, and the Anthropic-compatible option uses the Messages API. A Chat Completions-only gateway will not work with the configuration generated by the OpenAI-compatible setup option. A successful `doctor` check does not confirm a real model request. HTTP 401/403 usually indicates an authorization problem; 404 may indicate an incorrect URL or unsupported model. Check the provider's response and [Configuration](user/configuration.md).
- **Missing product resources or damaged installation:** reinstall OwnPI using the installer, then run `doctor` again. Report the error if it persists.
- **Brainlib is unavailable:** inspect `ownpi pack status neuroscience`. Install the optional Pack if absent, or enable it if disabled, then check it with `ownpi tools doctor brainlib`.

## Download or checksum failure

Check network access and retry the installer from [Getting Started](user/getting-started.md). If you received a private beta download address, follow the accompanying access instructions. Do not bypass TLS or checksum verification. Report repeated failures with the command and error text.

## Task appears stuck or was interrupted

Use `ownpi run list` to find the run ID, then check its state:

```bash
ownpi run status <run_id>
```

A background command returning a run ID does not mean the task is complete. Little terminal output does not by itself mean the run is stuck; work may be continuing in subagents. Compare State, Runtime active, Stage, and Last recorded activity. Recorded state can lag behind current execution, and an inactive Runtime alone does not establish success. See the [status field reference](user/cli-reference.md#ownpi-run-status).

After stopping a run or an unexpected process exit, continue in the foreground or background:

```bash
ownpi run resume <run_id>
ownpi run resume <run_id> --background
```

If the Runtime is still active and you want to restart its work, stop it first with Ctrl-C in its foreground terminal or `ownpi run stop <run_id>`. Cleanup may take a few seconds. Check that the Runtime has exited before resuming. Resume uses saved records and may repeat unfinished work. Keep the original workspace and resources available.

If `run list` cannot find a known run, check that you are using the original `OWNPI_HOME`. Changing the workspace directory does not switch app homes. For stopping and recovery behavior, see the [CLI Reference](user/cli-reference.md).

## Run completed but outputs are hard to find

Read the run's closing summary and inspect the research workspace. Final deliverables are usually under `<workspace>/output_synthesis/final_delivery/`, often with a delivery `README.md`, but the model chooses the actual directories and filenames. Follow the instructions and artifacts produced by that run rather than assuming a fixed path. `Run directory` in `run status` points to managed run records, not necessarily the deliverables.

`State: completed` describes execution state; it does not certify the quality or completeness of the scientific result. Check the actual files and reported limitations against your requested deliverables. Files from a stopped or failed run may be intermediate outputs.

## Clarification or permission commands appear in help

The current CLI still exposes compatibility commands for pending interactions. They are not required for the normal unattended Beta workflow and do not enable a supported interactive permission mode. Running them without a matching pending interaction does not create one. See [CLI Reference](user/cli-reference.md#compatibility-commands-still-visible-in-help) for their scope. Use `run stop` when you intend to stop and later resume work.

## Report a problem

Use GitHub Issues to provide the OwnPI version from `ownpi info`, operating system, command, run status, and steps to reproduce. Find the managed run directory in the Run directory field of `ownpi run status <run_id>`. If a diagnostic log exists, it is at `<run_dir>/diagnostics/runtime.jsonl`; include a relevant excerpt. Review logs before sharing and remove API keys, private URLs, data, and paths.
